# Smarter TemplateAutocomplete

## Problem
Two issues with the current autocomplete:

1. **Empty `{{` shows every option** — typing `{{` immediately dumps all variables + all node names into a huge list. The dropdown is overwhelming.
2. **`$('` shows every node name** — all upstream node names are listed as individual options (e.g. `$('Node1')`, `$('Node2')`, …, `$('Node20')`), which is noisy.

## Changes

### 1. Don't show autocomplete on empty `{{` (lines 347–392)
Remove the "empty `{{` — show all top-level suggestions" block entirely. Autocomplete should only appear once the user starts typing a prefix (e.g. `{{ $`, `{{ $('`, etc.).

### 2. Replace node-name listing with `$('…')` function pattern
Instead of listing each `$('Node1')`, `$('Node2')` as separate completion options:

- When the user types `{{ $('` (partial match, line 206–233): keep the filtered node-name suggestions — this is the actual search behavior the user wants.
- When the user types `{{ $(` (line 236–257): instead of listing all node names, show a **single** `$('…')` option with info text "Select a node". On accept, place the cursor inside the quotes so the user can type/search the node name, which will then trigger the partial-match suggestions.
- Remove the "empty `{{`" node options entirely (line 354–370).

### 3. Variable prefix (`$`) should still work with search
The `varPrefixMatch` handler (line 314–343) already requires the user to type `$`, so it's already search-based. Keep as-is but remove the `allVariables` additions for `$input` when there's no prefix — only show after `$` is typed.
